# shashwat-agent-skills

[![Validate skills](https://github.com/shashwatweb3/shashwat-agent-skills/actions/workflows/validate-skills.yml/badge.svg)](https://github.com/shashwatweb3/shashwat-agent-skills/actions/workflows/validate-skills.yml)

A production-ready, portable collection of [Agent Skills](https://agentskills.io/). Skills live once, under `skills/<skill-name>/SKILL.md`, and work across Agent Skills-compatible clients without duplication.

## Philosophy

- **Write once, run anywhere.** The same `SKILL.md` works for OpenCode, Codex CLI, and Claude Code.
- **Tool-agnostic by design.** Instructions describe *what* and *when* to do, not which vendor-specific UI to click.
- **Specification-first.** Validated against the [Agent Skills specification](https://agentskills.io/specification) and vendor docs ([OpenCode](https://opencode.ai/), [OpenAI Codex](https://developers.openai.com/codex/skills/), [Claude Code](https://code.claude.com/docs/en/skills)).
- **Dependency-free and auditable.** All tooling uses only Python 3.9+ standard library. No external packages to install or trust.
- **Evidence-driven.** Skills that audit or evaluate distinguish observed facts from assumptions and avoid unverifiable claims.

## Quick start

```bash
# Clone
git clone https://github.com/shashwatweb3/shashwat-agent-skills.git
cd shashwat-agent-skills

# Validate the whole repository
./scripts/validate-skills --strict

# List all skills
./scripts/list-skills
./scripts/list-skills --markdown
./scripts/list-skills --json
```

## Using a skill

Every skill is one `SKILL.md` under `skills/`. Pick whichever install method
suits you; the file itself never changes.

### Claude Code

```bash
claude plugin marketplace add shashwatweb3/shashwat-agent-skills
claude plugin install shashwat-agent-skills@shashwat-agent-skills
```

Or symlink a single skill into a project:

```bash
mkdir -p .claude/skills
ln -s /path/to/shashwat-agent-skills/skills/website-launch-safety \
        .claude/skills/website-launch-safety
```

See [`docs/claude-code.md`](docs/claude-code.md).

### Codex

```bash
codex plugin marketplace add shashwatweb3/shashwat-agent-skills
codex plugin add shashwat-agent-skills@shashwat-agent-skills
```

Or symlink a single skill into a project:

```bash
mkdir -p .agents/skills
ln -s /path/to/shashwat-agent-skills/skills/website-launch-safety \
        .agents/skills/website-launch-safety
```

See [`docs/codex.md`](docs/codex.md).

### OpenCode

Point OpenCode at the `skills/` directory in `opencode.json`. It loads every
skill in the repository, and keeps up as skills are added.

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "skills": {
    "paths": ["/path/to/shashwat-agent-skills/skills"]
  }
}
```

Or symlink a single skill into a project:

```bash
mkdir -p .opencode/skills
ln -s /path/to/shashwat-agent-skills/skills/website-launch-safety \
        .opencode/skills/website-launch-safety
```

See [`docs/opencode.md`](docs/opencode.md).

You never need to copy a skill into more than one place. If a client expects a
different directory, symlink from `skills/` rather than duplicating the file.

## Creating a new skill

1. `cp -r templates/skill skills/my-new-skill`
2. Edit `skills/my-new-skill/SKILL.md` (name and description are required; only `name`, `description`, `license`, `compatibility`, `metadata`, `allowed-tools` are allowed in frontmatter)
3. Add behaviour test cases under `tests/my-new-skill/` (`README.md`, `positive-cases.md`, `indirect-cases.md`, `non-trigger-cases.md`, `edge-cases.md`)
4. `./scripts/validate-skills --strict`
5. `./scripts/list-skills --markdown` and update the "Available skills" section above
6. `./tests/run-tests`

See [`templates/skill/README.md`](templates/skill/README.md) and [`CONTRIBUTING.md`](CONTRIBUTING.md) for the full workflow.

## Tooling

| Script | Purpose |
| --- | --- |
| `scripts/validate-skills` | Discovery, frontmatter validation, naming, links, UTF-8, duplicates, and template checks. Use `--strict` to treat warnings as errors. |
| `scripts/list-skills` | Lists skills discovered from `skills/`. Formats: text (default), `--markdown`, `--json`, `--details`. |
| `tests/run-tests` | Runs validator, behaviour-case coverage, unit tests, README/skill-list agreement, and script hygiene. |

All tooling is Python 3.9+ standard library only. No external dependencies.

## Behaviour test cases

Each skill ships with human-verifiable behaviour cases that document when it should and should not trigger, plus edge cases. These are not LLM-judged; they exist to make intent unambiguous. See [`tests/website-launch-safety/`](tests/website-launch-safety/) as the reference.

## Packaging

Skills stay canonical at `skills/`. The manifests only point at that directory;
none of them contains a `SKILL.md`.

| File | Read by | Purpose |
| --- | --- | --- |
| `plugin.json` | Portable Agent Plugins clients, including Codex | Plugin identity and metadata |
| `.claude-plugin/plugin.json` | Claude Code | The same identity, in Claude Code's location |
| `.claude-plugin/marketplace.json` | Claude Code | Lets `claude plugin marketplace add <repo>` work |
| `.agents/plugins/marketplace.json` | Codex | Lets `codex plugin marketplace add <repo>` work |

`skills/` is already the default skills location in both ecosystems, so no
manifest declares a `skills` path. The validator parses each manifest, requires
a kebab-case name, requires every path it names to exist, requires all
manifests to agree on the plugin name, and rejects any manifest that points at a
second copy of a skill.

The manifests are a **distribution layer only**. They carry identity and
metadata; they never carry instructions. The validator enforces that
`skills/` holds the only loadable `SKILL.md` in the repository, with
`templates/skill/SKILL.md` as the sole exception, so a platform-specific copy
cannot be committed by accident.

`templates/skill/SKILL.md` deliberately sits outside `skills/`, so it is a
starting point rather than a loadable skill.
